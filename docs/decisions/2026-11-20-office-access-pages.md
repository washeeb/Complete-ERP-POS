## The other People & access pages in the new back office
- **An IT Admin's "Give a branch" was rolled back.** Found by test: narrowing grants the branch and revokes the company-wide access inside one transaction; for IT the grant saved an approval request and then raised "sent for approval", which rolled the transaction back, request included. The screen still said "sent for approval". Fixed in AccessService for both the current and the new screen: IT's request is submitted first, outside that transaction, as one request for the whole change ("Limit company-wide access"); approving it runs the narrowing as a whole. The owner and SyncLytics support narrow at once, as before.
- **Staff cards showed every company's people.** Found by test: users carry no company scope of their own, and the current page did not filter by company, so a second company on the same server (such as a practice company) showed up. Both pages now filter by company. Printing for someone of another company was already refused by AccessService.
- **IT activity keeps the current list of what counts as technical,** including a person's own look changes logged as profile updates; it is the same audit query as now.
- **Who can do what** is the same review as now (risky combinations, notes, everyone's access, CSV), with names opening the user's page when you may see users.
