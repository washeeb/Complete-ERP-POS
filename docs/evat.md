# GRA E-VAT (Phase 13)

Owner decision (2026-10-29): build all three reporting modes; the developer/admin chooses per company (`evat.mode`): `realtime`, `daily`, `invoices` (default `off`).

- `FiscalService` records a `fiscal_submissions` row per document (unique per document): till sales (realtime/daily), invoices and credit notes (every mode except off; in daily mode invoices still go one by one). `FiscalRelay` (outbox consumer `fiscal`, in the relay loop) picks up committed sales (also offline ones), invoices and credit notes, and retries pending ones (back-off 1–360 min). Realtime till sales are also tried inline in `POST /pos/sales` with `GRA_EVAT_TIMEOUT` (default 8 s) so the code and QR print on the receipt (`sale.fiscal`); otherwise they follow within seconds. `erp:evat-batch` (every 15 min) sends daily-mode sales after `evat.daily_time`. GRA refusals (400/422) are `rejected` and wait for a person (Finance → GRA E-VAT → Send again).
- `FiscalAdapter` interface; `GraEvatAdapter` follows **GRA E-VAT API VER 8.2** (VSDC, published 2025-08): `POST {GRA_EVAT_URL}/api/v1/taxpayer/{GRA_EVAT_COMPANY_REFERENCE}/invoice` with header `security_key: GRA_EVAT_KEY`; `GET …/health` → `{"status":"UP"}` (System → Health, cached 5 min). Separate legal entities use their own reference and key from `GRA_EVAT_ACCOUNTS` (by seller TIN). The VSDC takes one document per call, so the daily batch sends them one after another (GRA down → the rest of the batch waits). Tests bind `fiscal.fake`; `GraEvatAdapterTest` checks the wire format with `Http::fake`.

## Document sent

`{currency, exchangeRate, invoiceNumber, totalLevy, userName, flag: INVOICE|PARTIAL_REFUND, calculationType: INCLUSIVE|EXCLUSIVE, totalVat, transactionDate (UTC ISO), totalAmount, totalExciseAmount, voucherAmount, businessPartnerName ("Cash customer"), businessPartnerTin ("C0000000000" for cash customers), saleType: NORMAL, discountType: GENERAL, discountAmount, reference, groupReferenceId, purchaseOrderReference, items: [{itemCode (SKU), itemCategory ("EXM" when untaxed), expireDate, description, quantity, levyAmountA (NHIL), levyAmountB (GETFund), levyAmountC (COVID-19), levyAmountD (CST), levyAmountE (tourism), discountAmount, exciseAmount, batchCode, unitPrice}]}` — amounts in cedis. A return or credit note is `PARTIAL_REFUND` with `invoiceNumber` = the original receipt / invoice and `reference` = the return / credit note number.

GRA's answer: `response.status` SUCCESS | ERROR; `response.mesaage` (sic; also `message`) holds `num, ysdcid, ysdcrecnum, ysdcintdata, ysdcregsig, ysdcmrc, ysdctime, flag, ysdcitems`; `response.qr_code` is the address for the QR. Stored reference = `ysdcid ysdcrecnum`; the receipt prints the whole signature block (`GraEvatAdapter::signature`). "ALREADY EXISTS" (GRA kept an earlier attempt) counts as reported. HTTP 401/403 (wrong key or reference) keeps documents waiting; ERROR / 400 / 422 is refused and waits for a person.

**Before production:** run the staging tests in manual 11.5. If GRA changes a field in a later API version, only `GraEvatAdapter` changes.
