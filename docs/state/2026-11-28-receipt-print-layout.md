## Desktop till receipts in the screen receipt's layout (branch `receipt-print-layout`, base `main`)
- **Found:** two receipt layouts. The screen receipt (`Receipt.tsx`, printed by the browser's print window) and the desktop till's silent ESC/POS print (`escpos.ts` via `hardware.printReceipt` → Tauri `print_raw`), used as soon as a receipt printer is chosen in the desktop till's settings. The ESC/POS layout was simpler (name line, "qty x price … total") and filled every line to exactly 48 characters; the client's printer wraps a completely full line, so every amount printed below its label. The company name at double width (24 characters) broke a 25-character name mid-word. Probed: the till's own bytes were exactly 48 per line, each amount beside its label.
- **`escpos.ts`:** `room` = width − 1 for columns and rules; `wrap()` and `wrapped()` (between words); company name double only when it fits `room / 2`, else bold and wrapped; item table on 80 mm (SN 3, Item, Qty 5, Price 8, Total 9; amounts without the currency, *Amounts in GHS*), names wrapping in the Item column; a unit too wide for Qty goes with the name; a row still too long falls back to name + "qty x price … total"; 58 mm keeps the two-line items.
- **Tests:** `escpos.test.ts` (10): no line reaches the width on 80 and 58 mm, each amount beside its label, long and short names, the carton unit and huge amounts.
- **To confirm on the client's printer:** print a sale after the update (the cause was the printer wrapping full lines; the layout now never fills one).
