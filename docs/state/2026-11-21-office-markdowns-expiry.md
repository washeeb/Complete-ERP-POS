## New back office, part 13: markdowns and expiry returns (branch `office-markdowns`, base `office-pharmacy-claims`)
- **Markdowns:** `BatchesScreen` takes an industry (`KINDS`: grocery → `GroceryMarkdowns`, pharmacy → `PharmacyMarkdowns`) and then runs that page (its stores, its access rule, `markdownsOnly`); `BatchesController` reads `industry` from the query or body (not `kind`: Add or move a batch already sends `kind` found/move). Client: `BatchesPage` with `industry`; `/admin/{grocery|pharmacy}/markdowns` → `/office/{grocery|pharmacy}/markdowns`.
- **Expiry & returns:** `App\Domain\Office\ExpiryScreen` (the list from `ExpiryService::batches`, options, the evidence setting) and `Office\ExpiryController` (dispose as a form with the certificate file, return, markdown skipping expired batches, the disposal register URL). Routes `office-api/expiry`, `expiry/options`, `expiry/register`, POST `expiry/dispose`, `expiry/return`, `expiry/markdown`. Client `pages/ExpiryPage.tsx`; `/admin/expiry-returns` → `/office/expiry`. A prepared disposal opens the rebuilt adjustment; a prepared return opens the current supplier return page (not rebuilt yet).
